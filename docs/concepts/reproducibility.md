# Reproducibility and evidence

Every reported observation should be traceable to an input, a processing step, and a reviewable source. Keep observations separate from interpretations and assumptions.

Record immutable input identifiers or hashes, code revision, explicit software versions, environment details, parameters, references, and output checks. Explain any manual edits. An environment name or script suffix is not a version record.

Use separate fields for execution status and scientific review. A successful exit code supports an execution claim; it does not establish that the design, normalization, or biological interpretation is appropriate. Historical logs can support a reported prior run, but a new inventory does not independently reproduce that run.

See [provenance conventions](../contributing/provenance.md) for connecting private source evidence to safe public documentation.
