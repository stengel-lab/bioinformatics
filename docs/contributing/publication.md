# Publication review

Before a page or example enters Git history, review its full contents, provenance, and rights to publish.

- Use original explanatory writing and permitted public or synthetic examples.
- Remove raw data, unpublished results, sensitive metadata, credentials, tokens, private hosts, account identifiers, local paths, and institutional configuration.
- Check code blocks, comments, screenshots, notebook outputs, embedded links, environment exports, and generated files.
- Keep the detailed private inventory and original scripts outside tracked content.
- Separate observed behavior, interpretation, and unverified assumptions. Do not imply scientific validation from an inventory or website build.
- Inspect the complete staged diff and file list before committing. An ignore rule does not prevent forced staging or protect already tracked files.
- Obtain the publication and scientific reviews recorded by the [review template](templates/review-record.md).

Select licensing terms with the maintainers before redistributing source material or promising reuse rights. A public repository alone does not settle licensing.
